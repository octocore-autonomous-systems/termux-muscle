# Termux Muscle 0.15.0

The default Claude Code pin moves from **2.1.289** to **2.1.291**. Musl stays at **1.2.6-r2**. The official vendor executable is unmodified; the npm archive integrity and extracted binary digest are recorded in `compatibility.json`.

## Why

[Claude Code 2.1.291](https://github.com/anthropics/claude-code/releases/tag/v2.1.291) fixes a regression in 2.1.290 where cloud sessions could drop answers to permission prompts and a regression in 2.1.288 where the last messages of a session could be lost when quitting. Termux Muscle never pinned 2.1.290, so this pin also brings its changes: `claude attach <name>` and `claude logs <name>` accepting part of a session name, new plugin hook fields (`serverToolUses`, `agentId`, `ceiling`), warnings about managed settings, and fixes for requests failing behind proxies that reject a beta header, long sessions with hundreds of images getting stuck, `WebFetch` silently dropping page text past 100,000 characters, scheduled tasks not coming back after compaction, conversation compaction failing with a null error, deny and ask rules missing commands named through a variable prefix, and `Read` deny rules not applying to pasted image paths, plus a range of plugin, mod, agents view and `/ultrareview` issues. These are upstream changes; Termux Muscle acceptance tests the lifecycle and the bounded tool workflow described below, not every upstream feature.

## Pin history

Claude Code **2.1.289** is retained as formerly pinned by Termux Muscle **0.14.0**, using the [0.14.0 maintainer report](../../compatibility/galaxy-s26-ultra-0.14.0-20261004.md). The current pin starts with **0.15.0**. Earlier history is unchanged.

## Device evidence

Fresh device and authenticated tool acceptance is pending. This preparation does not assert verification for 0.15.0.

## Updating an existing installation

After this release is published, run from a native Termux shell:

```sh
termux-muscle self-update
termux-muscle update
claude --version
```

The final command should report `2.1.291 (Claude Code)`. A previous validated runtime remains available through `termux-muscle rollback`.

## Known limitations

Acceptance covers one device and configuration. Interactive UI, background and screen-off operation, custom hooks, MCP tool calls, and other models require separate evidence. Documented model minimums and account entitlements are unchanged. Installing any version other than the current pin still requires `--allow-unverified`.
