# Termux Muscle 0.7.0

This version reorganizes the command-line help and adds a way to see which Claude Code versions can be installed. The Claude Code pin stays at **2.1.283** and musl at **1.2.6-r2**.

## Grouped help

In 0.6.0, `termux-muscle --help` listed fourteen commands in one flat list, so it was unclear which commands acted on Claude Code and which on Termux Muscle itself. The overview is now grouped by what each command acts on:

```text
Claude Code:
  install      Install the pinned Claude Code release and put claude on PATH
  ...
Termux Muscle:
  self-update  Upgrade Termux Muscle itself (not Claude Code)
  ...
Troubleshooting (checks the device, Termux Muscle and Claude Code together;
read-only, nothing is uploaded):
  doctor       Check that the device, the claude launcher and the active
               Claude Code release all work, without contacting Anthropic
  ...
```

- The overview also shows the default `--root` and `--prefix` paths and a short list of common tasks.
- Details from the old closing paragraph now appear in the help for the command they belong to: exit statuses and progress in `self-update --help`, version selection in `install --help` and `update --help`.
- `termux-muscle help COMMAND` prints the same text as `COMMAND --help`, and Bash completion completes the command name.
- Command names and options are unchanged.

## Active Claude Code version

`--version` keeps its first line unchanged and adds a second line when a release is active:

```text
Termux Muscle 0.7.0
Claude Code 2.1.283 (active)
```

A fresh or damaged installation prints only the first line. Scripts that compare the entire output with `Termux Muscle X.Y.Z` should compare only the first line.

## Available versions

`termux-muscle versions --available` lists Claude Code releases published for the official ARM64 musl package, newest first:

```text
VERSION    RELEASED    STATUS
2.1.283    2026-09-25  pinned, active, latest, next
2.1.282    2026-09-24  unverified
...
2.1.274    2026-09-16  unverified, stable
```

- **pinned** marks the version this Termux Muscle release was accepted with. Every other version is **unverified**.
- **active** and **retained** mark installed releases. Tags such as `latest` and `stable` come from the registry.
- By default, the listing shows the ten newest releases plus every pinned, active or retained release. `--all` lists every release. `--json` prints a `termux-muscle.available.v1` object.
- The listing reads one registry document over HTTPS without following redirects. It downloads no archive and changes no state.
- Installing a version other than the pin still needs `update --claude-version X.Y.Z --allow-unverified`.

## Known limitations

- `versions --available` needs network access to the npm registry. It has no offline mode and no cache.
- A listed unverified version has not passed Termux Muscle acceptance, even if it is tagged `latest` or `stable` upstream.

## Device evidence

[Dated device evidence](../../compatibility/galaxy-s26-ultra-0.7.0-20260927.md) from a Samsung Galaxy S26 Ultra (Android 16, Termux 0.118.3) covers `make check` (all 15 test programs passed, including the new help, version and listing regressions) and maintainer acceptance: private source installation, isolated startup, offline update and rollback, removal and one bounded authenticated **Opus 5.5** shell-tool workflow, with the live installation unchanged.

Run acceptance from a **fresh native Termux shell that is not inside Claude Code**, in a clean checkout of the release commit:

```sh
scripts/maintainer_acceptance.sh --model claude-opus-5-5
```

## Updating an existing installation

From a fresh Termux shell:

```sh
termux-muscle self-update
```
