# Termux Muscle 0.4.0

This version moves the default Claude Code pin from **2.1.270** to **2.1.283** and documents **Opus 5.5**.

Opus 5.5 (`claude-opus-5-5`) is documented upstream as requiring client **2.1.280 or later**. The 2.1.270 pin is below that minimum, so a default installation could not select the model; the release gate also rejects a manifest whose documented models require a newer client than the pinned one. Moving the pin to 2.1.283 resolves both.

| Pinned payload | 0.3.2 | 0.4.0 |
| --- | --- | --- |
| Claude Code | 2.1.270 | 2.1.283 |
| musl loader | 1.2.6-r2 | 1.2.6-r2 |

The recorded source identity for 2.1.283 is Anthropic's official ARM64 musl package, unmodified:

| Tarball | `https://registry.npmjs.org/@anthropic-ai/claude-code-linux-arm64-musl/-/claude-code-linux-arm64-musl-2.1.283.tgz` |
| Registry integrity | `sha512-JcZDkbhkSdyuwSmZUlzEXOQiIn4U8vGwbxkU/MoFymU93RfmpmOUnj3TZALyNll0t86b0IpiYCXWFfaKu7ZUUw==` |

## Device evidence

[Dated device evidence](../../compatibility/galaxy-s26-ultra-0.4.0-20260927.md) from a Samsung Galaxy S26 Ultra (Android 16, Termux 0.118.3) covers private source installation, isolated startup, offline update and rollback, removal and one bounded authenticated **Opus 5.5** shell-tool workflow. The report binds to the tested source commit and a clean tree, and the live installation was proven unchanged. Ordinary command takeover, indexed manual discovery, interactive and background use, and MCP tool calls are outside this release's fresh acceptance.

The evidence was produced by the new `scripts/maintainer_acceptance.sh`. Run it from a **fresh native Termux shell that is not inside Claude Code**, in a clean checkout:

```sh
scripts/maintainer_acceptance.sh --model claude-opus-5-5
```

Inside a managed Claude Code session, the runtime's nested-namespace guard refuses to start a candidate release (`runtime_nested_conflict`), so the script refuses to run there and explains why. It also refuses a checkout with uncommitted or untracked files, because such evidence would describe no commit.

## Updating an existing installation

From a fresh Termux shell, update the manager, then the runtime:

```sh
termux-muscle self-update
termux-muscle update
```

A 0.3.x manager's `update` uses its own 2.1.270 pin, so run `self-update` first. Either way the candidate must pass its startup checks before activation, and `termux-muscle rollback` restores the previous local release without a download.
