# Termux Muscle 0.24.0

This release changes where Termux Muscle downloads the musl loader, so that a rebuild at Alpine Linux can no longer break new installations. It also moves the tested pin to Claude Code **2.1.329**, the release Anthropic's `latest` channel names. Nothing else changes in how Claude Code is acquired, verified, installed or run.

## Musl from an Alpine release archive

Anthropic builds Claude Code for Linux with musl. Termux Muscle supplies musl's loader, `ld-musl-aarch64.so.1`, from Alpine Linux and checks it against SHA-256 values in `compatibility.json` before using it.

Up to 0.23.0 the pinned address was the musl package in Alpine's rolling repository, `https://dl-cdn.alpinelinux.org/alpine/v3.24/main/aarch64/musl-VERSION.apk`. Alpine replaces that file whenever it rebuilds musl and removes the old one. From that day the pinned download returns 404, and a first installation, or an install, update or repair on a device that no longer has the file in its cache, stops at `download_failed`. A device with the file cached keeps working, so nothing looks wrong on an existing installation. This happened to 0.22.0 after Alpine published `musl-1.2.6-r3.apk` on 2026-10-21. 0.23.0 repaired new installations on 2026-11-13 by pointing at r3, which the next rebuild would break again.

0.24.0 pins the root filesystem archive of a numbered Alpine release instead:

| Field | Value |
| --- | --- |
| `musl.url` | `https://dl-cdn.alpinelinux.org/alpine/v3.24/releases/aarch64/alpine-minirootfs-3.24.4-aarch64.tar.gz` |
| `musl.sha256` | `4b14c18f7e90a063b61462ea1462a5732c154bf6adad594974fe6487cd98a8de` |
| `musl.loader_sha256` | `53282acc2be8a08a9fdcf880334bf35bbfd0a13862b7f3616be3919fcda11793` (unchanged) |
| `musl.native_loader_sha256` | `1c831881bac74b51f3f6f1f39b20052badcca92431476fbf3f889d39b7b17727` (unchanged) |

Alpine publishes each release archive once and keeps it. On 2026-11-13 it still served every archive back to Alpine 3.5.0 of December 2016. That is Alpine's practice, not a written promise, and the SHA-256 check is unchanged: a changed file is refused, never used. The loader inside the 3.24.4 archive is byte for byte the one 0.23.0 pins, so the loader and the configured native loader keep their digests. Only `lib/ld-musl-aarch64.so.1` is taken from the archive; the rest of it is skipped and never installed, and an archive whose `lib` is a link is refused. The download grows from about 0.4 MB to about 4 MB.

The release gate (`tm-core release-check`) refuses a musl package address in a new release. The downloader still accepts one in a receipt, because releases installed by 0.23.0 and earlier record it and are repaired and rolled back from their receipts and cached archives.

## Compatibility

A receipt written by 0.24.0 names the release archive. 0.23.0 and earlier cannot read that address, so going back to an older Termux Muscle cannot repair or roll back a Claude Code release installed by 0.24.0. That change in what stored data means is why this release is 0.24.0 and not 0.23.1. Releases installed before the upgrade keep working and remain repairable.

## Pin

The tested pin moves from 2.1.323 to **2.1.329** (`claude.pinned_since` 0.24.0). The npm integrity is the registry's, and `binary_sha256` is the `linux-arm64-musl` checksum in Anthropic's signed manifest for 2.1.329. 2.1.323 joins `pin_history` (pinned by 0.23.0, verified on 2026-11-13). Installations follow Anthropic's channel regardless; the pin is the device-tested baseline and the `--offline` default.

## Upgrading

`termux-muscle self-update` upgrades the manager and leaves the active Claude Code release as it is.

## Known limitations

Acceptance covers one device and configuration. Interactive use, background and screen-off operation, custom hooks, MCP tool calls and other models require separate evidence. Other limitations are unchanged from [0.21.0](0.21.0.md#known-limitations).
