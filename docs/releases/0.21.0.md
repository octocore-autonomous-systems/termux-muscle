# Termux Muscle 0.21.0

Two changes to how Termux Muscle works, and one to how it is released. `termux-muscle update` now follows Anthropic's release channel and admits a version on Anthropic's own signature. Claude Code now runs as an ordinary process, without PRoot, by default. And Termux Muscle stops cutting a release for every Claude Code version. The tested pin stays at Claude Code **2.1.296**; musl stays at **1.2.6-r2**.

## Why

From 0.8.0 to 0.20.0 this project released thirteen times in eleven days, and each release said that no harness code had changed. The manager installed only the version it pinned, so every upstream build needed a release, a device run and a model request before an installation could have it. Meanwhile PRoot, which supplied the two paths Android lacks, traced every system call of Claude Code and of every command it ran: measured through the Bash tool on the reference device, process creation was 3 times slower and file-heavy commands 3 to 5 times slower than in a plain shell. Both costs came from the design, not from Claude Code or Android.

## Updates follow the release channel

`termux-muscle update`, and `claude update`, which runs it, installs the version Anthropic's `latest` channel names. `--claude-version stable` follows Anthropic's delayed channel, `--claude-version X.Y.Z` names one release, and `--claude-version pinned` selects the release this project version was device-tested with, which is also the default with `--offline`.

A release other than the pin is installed only when Anthropic's detached signature on that release's `manifest.json` verifies against Anthropic's release signing key, which is built into the manager with its fingerprint, and the executable from the official npm package has the SHA-256 that manifest signs. It must then pass the same isolated startup checks as before. A bad signature, a signature by any other key, a genuine signature for a different version and a different executable all leave the active release untouched. `--allow-unverified` is the only way past the signature. A channel never replaces the active release with an older one.

## Claude Code runs without PRoot

A release is now prepared once, at installation, after its downloads are verified:

- the installed executable's loader path is set to the release's own copy of the musl loader, leaving Anthropic's code and data unchanged;
- three constants in that private loader copy are replaced, so it reads its nameservers from a file descriptor and leaves `LD_PRELOAD` and `LD_LIBRARY_PATH` to the Android programs they are meant for;
- a small object of ours opens the resolver file when a Claude Code process starts.

Claude Code and everything it starts are then ordinary Termux processes, untraced, with the caller's environment intact; termux-exec stays preloaded in the tools Claude runs, so `#!/usr/bin/env` scripts work as in any Termux shell. [architecture.md](../architecture.md#launch-two-backends) lists exactly what changes and how it is verified.

The PRoot backend is unchanged: `termux-muscle update --backend proot` runs the downloaded bytes as they are. The backend belongs to a release, `termux-muscle versions` shows it, and `rollback` crosses between them. Three things differ on the native backend. Hooks run through `/bin/sh`, which is Android's shell and not Bash. A script that Claude Code starts directly, without a shell, cannot begin with `#!/usr/bin/env`; this mainly means an MCP server configured as a bare script path. And `/tmp` is not writable, as in any Termux shell; `TMPDIR` is.

## Also in this release

`update` and `cleanup` now remove cached source archives that neither the pin nor a retained release refers to; earlier versions kept every archive they downloaded. `gpgv` and `patchelf` become prerequisites and the installer adds them. The scheduled upstream tracker and the pin-only release helpers are gone from the repository.

## Device evidence

[Fresh device evidence](../../compatibility/galaxy-s26-ultra-0.21.0-20261010.md) from Samsung Galaxy S26 Ultra, Android 17 / API 37, Termux 0.118.3 (GitHub) records all **15 C and shell test programs passing** in a native shell and acceptance from clean commit `5026120` on the native backend. Private source install, isolated version/help/init, the shell environment check, offline update and rollback, and uninstall passed with the live installation unchanged.

One bounded authenticated **Opus 5.5** (`claude-opus-5-5`) request produced exactly one successful Bash-tool fixture call, verifying a portable shebang and ripgrep from an untraced tool process. The exact model was observed; capture exited 0 in 4846 ms. The PRoot backend was then installed from the same verified cache and passed its startup checks.

In a separate disposable root, `update` read Anthropic's live channel, and `update --claude-version 2.1.295` verified Anthropic's signature and the signed executable digest before activating that release. Through the Bash tool, process creation measured 2.6 to 3.2 times faster on the native backend than under PRoot, and `git status`, reading a source tree and `grep -r` 2.9 to 5.2 times faster, over two runs.

The optional runtime host probes and unavailable cross-UID executable fixture were skipped in the deterministic suite; the host probes passed separately the same day. Public HTTPS delivery and command/manual takeover were not retested. Sonnet 5.5 and Fable 5.1 remain documented, not verified.

## Updating an existing installation

After this release is published, run from a native Termux shell:

```sh
termux-muscle self-update
termux-muscle update
termux-muscle versions
```

`self-update` leaves the active Claude Code release as it is, on the PRoot backend. `update` installs the next release Anthropic publishes on the native backend; if the active version is already current it changes nothing, and `termux-muscle update --claude-version X.Y.Z` installs that same version again natively. A running session keeps the release it started with. The previous release remains available through `termux-muscle rollback`.

## Known limitations

Acceptance covers one device and configuration. Interactive use, background and screen-off operation, custom hooks, MCP tool calls and other models require separate evidence. If Anthropic replaces its release signing key, signed installs fail closed until a Termux Muscle release carries the new key; the pin and `--allow-unverified` remain available meanwhile. The native backend needs an installation path without spaces or colons.
