# Termux Muscle 0.22.0

This release gives the `termux-muscle` command one PATH entry instead of two, and moves the tested pin to Claude Code **2.1.299**, the release Anthropic's `latest` channel names. Musl stays at **1.2.6-r2**. Nothing changes in how Claude Code is installed or run.

## One command entry for the manager

Since 0.2.0 installation linked the manager into both `$PREFIX/bin/termux-muscle` and `~/.local/bin/termux-muscle`, two symlinks to the same owned launcher. Termux puts both directories on PATH, so `type -a termux-muscle` listed two commands and `compgen -c termux-` printed `termux-muscle` twice. The second entry added nothing: `$PREFIX/bin` is always on Termux's PATH.

The manager is now linked only into `$PREFIX/bin`. If an unrelated command named `termux-muscle` already holds that entry, it is preserved, as before, and the manager is linked into `~/.local/bin` instead. Once the prefix entry is owned, installation and `self-update` restore the owned `~/.local/bin` entry that earlier releases created. Restoring goes through the same ownership journal as uninstall: that entry's recorded original is "missing", so the link is removed. A `~/.local/bin/termux-muscle` that Termux Muscle does not own is never touched.

Claude command entries (`$PREFIX/bin/claude`, `~/.local/bin/claude` and the PATH winner) are unchanged. The `~/.local/bin/claude` entry deliberately takes over the location Anthropic's own installer uses.

## Pin

The tested pin moves from 2.1.296 to **2.1.299** (`claude.pinned_since` 0.22.0). The npm integrity is the registry's, and `binary_sha256` is the `linux-arm64-musl` checksum in Anthropic's signed manifest for 2.1.299. 2.1.296 joins `pin_history` (pinned by 0.20.0 through 0.21.1, verified on 2026-10-13). Installations follow Anthropic's channel regardless; the pin is the device-tested baseline and the `--offline` default.

## Upgrading

`termux-muscle self-update` upgrades the manager, removes the redundant `~/.local/bin/termux-muscle` link and leaves the active Claude Code release as it is. A shell that already ran `termux-muscle` may have cached the removed path: run `hash -r` or open a new shell.

## Device evidence

[Fresh device evidence](../../compatibility/galaxy-s26-ultra-0.22.0-20261014.md) from Samsung Galaxy S26 Ultra, Android 17 / API 37, Termux 0.118.3 (GitHub) records all **15 C and shell test programs passing** and acceptance from clean commit `6fdb9a3` on the native backend, run from inside a Claude Code session. Private source install of the new **2.1.299** pin, isolated version/help/init, the shell environment check, offline update and rollback, and uninstall passed with the live installation unchanged.

One bounded authenticated **Opus 5.5** (`claude-opus-5-5`) request produced exactly one successful Bash-tool fixture call, verifying a portable shebang and ripgrep from an untraced tool process. The exact model was observed; capture exited 0 in 6465 ms. The PRoot backend was then installed from the same verified cache and passed its startup checks.

The optional runtime host probes and unavailable cross-UID executable fixture were skipped in the deterministic suite. The live upgrade from two manager entries to one is covered by the regression test and by the device's own upgrade after publication. Public HTTPS delivery and command/manual takeover were not retested. Sonnet 5.5 and Fable 5.1 remain documented, not verified.

## Known limitations

Acceptance covers one device and configuration. Interactive use, background and screen-off operation, custom hooks, MCP tool calls and other models require separate evidence. Other limitations are unchanged from [0.21.0](0.21.0.md#known-limitations).
