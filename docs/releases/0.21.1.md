# Termux Muscle 0.21.1

A patch release with one fix: the test suite, and so the installer and `termux-muscle self-update`, now work when started from inside a Claude Code session on the native backend. Nothing changes in how Claude Code is installed or run. The tested pin stays at Claude Code **2.1.296**; musl stays at **1.2.6-r2**.

## What was wrong

Since 0.21.0 Claude Code runs as an ordinary Termux process, and the launcher gives it, and every command it runs, three variables: `TM_RESOLV_CONF` (the resolver file), `SSL_CERT_FILE` (the certificate bundle) and `CLAUDE_CODE_TMPDIR` (a writable scratch directory). The launcher also reads the first two as overrides and keeps a `CLAUDE_CODE_TMPDIR` it is given.

`tests/test_runtime.sh` launches fixtures and checks the exact resolver, certificate and scratch paths they receive. Run from inside a session, those fixtures inherited the session's values, and the suite stopped at `FAIL runtime: missing precise bind`. The installer runs the suite before it changes anything, so an installation or `self-update` started from a session was refused with "local tests failed; the managed installation was not changed". The refusal was safe, and wrong: nothing in the launcher was at fault.

A plain Termux shell, CI and a scheduled update service set none of these variables, which is why 0.21.0 passed its own acceptance.

## The fix

`tests/run.sh`, which already replaces an inherited `TM_CORE` with the checkout's own helper, now also clears `TM_RESOLV_CONF`, `SSL_CERT_FILE` and `CLAUDE_CODE_TMPDIR` before running any test program. Tests that exercise the overrides set them explicitly, as before. `tests/test_run.sh` runs the runner with all three set and fails if a test program sees one.

## Upgrading

`termux-muscle self-update` from a Termux shell upgrades the manager and leaves the active Claude Code release as it is. From inside a Claude Code session on 0.21.0 it also works, because the new release's own suite is the one that runs.

## Known limitations

Acceptance covers one device and configuration. Interactive use, background and screen-off operation, custom hooks, MCP tool calls and other models require separate evidence. Other limitations are unchanged from [0.21.0](0.21.0.md#known-limitations).
