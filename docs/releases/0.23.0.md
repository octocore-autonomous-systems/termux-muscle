# Termux Muscle 0.23.0

This release rewrites what `termux-muscle versions` and `termux-muscle versions --available` print, and moves the tested pin to Claude Code **2.1.323**, the release Anthropic's `latest` channel names. It also moves the musl pin to **1.2.6-r3**, because Alpine no longer serves the pinned 1.2.6-r2 archive and new installations failed. Nothing else changes in how Claude Code is acquired, verified, installed or run.

## Listings that describe the device, not the project's history

Since 0.21.0 an installation follows Anthropic's release channel, so the active release is normally newer than the release this project pinned. `versions --available` labelled every release that was not a pin `unverified`:

```
VERSION    RELEASED    STATUS
2.1.323    2026-11-12  unverified, active, latest, next
2.1.322    2026-11-10  unverified, retained
2.1.321    2026-11-09  unverified
```

That read as a fault in Termux Muscle or in Claude Code, to the project's own maintainer among others. It was neither. The word meant "this project has not run its own device test on that release". Anthropic signs every release listed, and `update` installs one only after that signature verifies against the release key built into the manager, the executable matches the signed SHA-256 and the release passes the isolated startup checks.

The listing now answers the questions a user has:

```
VERSION    RELEASED    ON THIS DEVICE  NOTES
2.1.323    2026-11-12  active          latest, next
2.1.322    2026-11-10  installed
2.1.321    2026-11-09
```

- `ON THIS DEVICE` shows `active` for the release in use and `installed` for one kept for rollback.
- `NOTES` names Anthropic's channels (`latest`, `stable`), marks the pin (`pinned: device-tested with this Termux Muscle`), and reports `deprecated by Anthropic` or `no longer published`.
- `installed without the signature check` appears only for a release that really was installed with `--allow-unverified`. It is the one row that deserves attention.
- The default view shows the ten newest releases plus the pin and the installed ones, so it fits one screen. `--all` lists every release and marks those earlier Termux Muscle versions were device-tested with (`device-tested with Termux Muscle 0.20.0 to 0.21.1`).
- The footer says how a release is checked before it runs, and that the pin is what `--claude-version pinned` and `--offline` install.

`termux-muscle versions`, the installed view, changes the same way:

```
Role       Claude Code    Backend   Verified by
Current    2.1.323        native    Anthropic's signature
Previous   2.1.322        native    Anthropic's signature
```

`Verified by` reads `Anthropic's signature`, `this project's device-tested pin` or `nothing (installed with --allow-unverified)` where the old `Source policy` column printed `signed`, `pinned` or `unverified`. The backend moved from the fourth column to the third; a script that read it by position needs the new column. Both `--json` outputs are unchanged.

## Pin

The tested pin moves from 2.1.299 to **2.1.323** (`claude.pinned_since` 0.23.0). The npm integrity is the registry's, and `binary_sha256` is the `linux-arm64-musl` checksum in Anthropic's signed manifest for 2.1.323. 2.1.299 joins `pin_history` (pinned by 0.22.0, verified on 2026-10-14). Installations follow Anthropic's channel regardless; the pin is the device-tested baseline and the `--offline` default.

## Musl 1.2.6-r3: new installations work again

Termux Muscle downloads one pinned Alpine package for the musl loader and C library and checks its SHA-256. Alpine 3.24 replaced `musl-1.2.6-r2.apk` with `musl-1.2.6-r3.apk` (built 2026-10-22) and removed the old file, so the pinned URL returned 404. A first installation of 0.22.0 failed with `download_failed: Official source download failed`, and so did an install, update or repair on any device that no longer had the archive in its cache. A device with the archive cached kept working, which is why a running installation showed nothing.

0.23.0 pins `musl-1.2.6-r3.apk` (SHA-256 `2e17864102278d9049c3a56f1bceed9e8cf287065617e579325123443daed8a5`), its loader (`53282acc…1793`) and the configured native loader (`1c831881…7727`). Before pinning, the archive's embedded Alpine signature was verified against Alpine's published key `alpine-devel@lists.alpinelinux.org-616ae350` (the same key from alpinelinux.org and from Alpine's aports repository), its data hash was checked against the signed control segment, and three mirrors returned identical bytes. Releases already installed keep the loader they were built with; a release installed from now on uses r3.

The same thing will happen when Alpine next rebuilds musl. Until the manager can follow that itself, it takes a Termux Muscle release to move this pin.

## Upgrading

`termux-muscle self-update` upgrades the manager and leaves the active Claude Code release as it is.

## Device evidence

[Fresh device evidence](../../compatibility/galaxy-s26-ultra-0.23.0-20261113.md) from Samsung Galaxy S26 Ultra, Android 17 / API 37, Termux 0.118.3 (GitHub) records all **15 C and shell test programs passing** and acceptance from clean commit `5142f9f` on the native backend, run from inside a Claude Code session. Private source install of the new **2.1.323** pin from an empty cache, which downloads and verifies musl **1.2.6-r3**, isolated version/help/init, the shell environment check, offline update and rollback, and uninstall passed with the live installation unchanged.

One bounded authenticated **Opus 5.5** (`claude-opus-5-5`) request produced exactly one successful Bash-tool fixture call, verifying a portable shebang and ripgrep from an untraced tool process. The exact model was observed; capture exited 0 in 7732 ms. The PRoot backend was then installed from the same verified cache and passed its startup checks.

The optional runtime host probes and unavailable cross-UID executable fixture were skipped in the deterministic suite. The listings are covered by the regression tests, not by the acceptance script. Public HTTPS delivery and command/manual takeover were not retested. Sonnet 5.5 and Fable 5.1 remain documented, not verified.

## Known limitations

Acceptance covers one device and configuration. Interactive use, background and screen-off operation, custom hooks, MCP tool calls and other models require separate evidence. Other limitations are unchanged from [0.21.0](0.21.0.md#known-limitations).
