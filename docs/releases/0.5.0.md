# Termux Muscle 0.5.0

This version makes the management tool's `self-update` quiet by default, adds `--verbose` and `--json` modes, and adds Bash completion generated from one command-line schema. The Claude Code pin stays at **2.1.283** and musl at **1.2.6-r2**.

| Pinned payload | 0.4.0 | 0.5.0 |
| --- | --- | --- |
| Claude Code | 2.1.283 | 2.1.283 |
| musl loader | 1.2.6-r2 | 1.2.6-r2 |

## Quiet self-update

Ordinary `termux-muscle self-update` output names release verification, local build, tests and installation as each stage starts. During tests, one dot means one top-level C or shell test program has passed; the line wraps after 60 dots and ends with passed, skipped and failed program totals. Compiler commands and individual PASS lines go to a private full log. On failure, the command names the stage and keeps that log at the printed path.

- `-V` or `--verbose` streams the full installer, build and test transcript.
- `--json` emits one `termux-muscle.self-update.v1` object on stdout with the result, exit code, error code, message and the complete combined transcript as base64, split into verification, build, test and installation stages when the installer marks them. Exit statuses stay 0/1/2/3.

**The first self-update from 0.4.0 still prints everything.** The running manager asks for quiet mode and the downloaded installer honors it. A 0.4.0 manager does not ask, so its update to 0.5.0 shows the full transcript. Self-updates started by a 0.5.0 or newer manager are quiet; `termux-muscle self-update --force` from 0.5.0 shows the new output.

## Command-line schema and completion

`scripts/cli_schema.py` defines the command line with argparse and generates `lib/cli_schema.sh`, which provides help text and Bash completion (`docs/completions/termux-muscle.sh`). Installation adds the completion file and uninstall removes it. The generator is a maintainer tool: the installer uses the generated shell file and never runs Python.

## Maintainer tooling

- The upstream release tracker checks Anthropic's ARM64 musl package every six hours and opens one compatibility-testing issue per newer version. Its checklist now points at `scripts/maintainer_acceptance.sh`. See [release tracking](../release-tracking.md).
- `scripts/maintainer_acceptance.sh` now explains the model-check cost: a subscription login (Pro or Max over OAuth) uses plan usage and is not billed; an API key is billed, capped at $0.50. The report's `total_cost_usd` is an estimate at API prices.

## Device evidence

Device acceptance for 0.5.0 has not been registered yet. Run it from a **fresh native Termux shell that is not inside Claude Code**, in a clean checkout of the release commit:

```sh
scripts/maintainer_acceptance.sh --model claude-opus-5-5
```

## Updating an existing installation

From a fresh Termux shell:

```sh
termux-muscle self-update
```

The Claude Code pin is unchanged, so `termux-muscle update` has nothing new to install after this release.
