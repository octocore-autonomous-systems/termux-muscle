# Termux Muscle 0.5.1

This version fixes quiet and JSON `self-update` from 0.5.0. The Claude Code pin stays at **2.1.283** and musl at **1.2.6-r2**.

## The problem

In 0.5.0, a quiet or `--json` self-update exports its stage-event and progress variables for the downloaded installer, and the installer's `make check` passed them on to every test program. `tests/test_bootstrap.sh` runs a nested installer with a minimal mock `PATH`. That nested installer saw the variables, tried to record a stage in the caller's event file without `wc`, and failed, so the update stopped during tests:

```text
Running test programs: ..
Tests: 2 passed, 0 skipped, 1 failed.
termux-muscle: update_failed: during test: ...
```

No installation was changed. `self-update --verbose` unsets these variables and was not affected. Ordinary `make check` and maintainer acceptance do not set them, which is why neither caught it.

## The fix

`tests/run.sh` reads the progress mode once, then unsets the self-update variables and closes the progress descriptor for each test program. Only the runner prints dots and totals. The new `tests/test_run.sh` runs a copy of the runner in a self-update environment and checks that a probe test sees none of that state.

The fix is in the downloaded source, so the 0.5.0 manager can install 0.5.1 with the ordinary quiet self-update.

## Device evidence

Device acceptance for 0.5.1 has not been registered yet. Run it from a **fresh native Termux shell that is not inside Claude Code**, in a clean checkout of the release commit:

```sh
scripts/maintainer_acceptance.sh --model claude-opus-5-5
```

## Updating an existing installation

From a fresh Termux shell:

```sh
termux-muscle self-update
```
