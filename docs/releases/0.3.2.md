# Termux Muscle 0.3.2

This release gives `termux-muscle self-update` explicit exit statuses so scripts can distinguish a completed manager update from a no-op:

| Status | Meaning |
| --- | --- |
| `0` | A newer manager was installed, or a requested compatible forced reinstall/downgrade completed. |
| `1` | Version validation, download, integrity, local build/test or installer failed. |
| `2` | The requested or latest manager version is already installed (`already_current`). |
| `3` | The requested or latest manager version is older (`target_older`). |

No-update notices go to stderr. For `2` or `3`, the installer is not downloaded or run. `-f` and `--force` still permit intentional compatible reinstalls or downgrades and never bypass checksum, build, ownership or minimum tooling compatibility checks. Signal interruption may use the shell's signal status.

Run in native ARM64 Termux:

```sh
termux-muscle self-update --version 0.3.2
```

For a new installation:

```sh
curl -fsSL https://github.com/octocore-autonomous-systems/termux-muscle/releases/download/v0.3.2/install.sh | sh
```

The pinned, unmodified Claude Code 2.1.270 and musl 1.2.6-r2 payloads are unchanged. [Dated device evidence](../../compatibility/galaxy-s26-ultra-0.3.2-20260924.md) records the fresh acceptance scope. Prior reports remain separate. Ordinary command takeover, interactive/background operation and MCP tool calls are outside this release's fresh private acceptance.
