# Termux Muscle 0.9.0

This version carries the **Claude Code pin history**, so a version an earlier Termux Muscle release accepted is no longer shown as unverified once the pin moves on. The Claude Code pin stays at **2.1.284** and musl at **1.2.6-r2**.

## Why

Before 0.9.0, `versions --available` labelled a version `pinned` only when it matched the one field `claude.version` in the installed manager's `compatibility.json`. Everything else was `unverified`, including 2.1.283, which 0.4.0 through 0.7.0 accepted on a real device, and 2.1.270 before it. The evidence was in `compatibility/`; the manager could not see it.

## The manifest

`compatibility.json` gains two fields:

- `claude.pinned_since`: the project release that first pinned the current Claude Code version (`0.8.0` for 2.1.284).
- `pin_history`: one entry per earlier pin, naming its exact version, the first and last project releases that pinned it (`project_versions.first` and `.last`), its acceptance date (`verified_on`) and the maintainer report of the last of those releases (`report`).

This release records:

| Claude Code | Termux Muscle releases | Accepted | Report |
| --- | --- | --- | --- |
| 2.1.270 | 0.1.0 to 0.3.2 | 2026-09-24 | `compatibility/galaxy-s26-ultra-0.3.2-20260924.json` |
| 2.1.283 | 0.4.0 to 0.7.0 | 2026-09-27 | `compatibility/galaxy-s26-ultra-0.7.0-20260927.json` |

## What the release gate checks

Every history entry is validated against its report: exact version, the report's project and Claude Code versions, maintainer provenance, every required lifecycle check PASS, and dates in order. Ranges must be ordered, non-overlapping and end before `pinned_since`. When the pin moves, the outgoing version must be appended: every `docs/releases/X.Y.Z.md` older than `pinned_since` must fall inside exactly one history range, otherwise `release-check` refuses with "missing from pin_history". Generated release notes gain a pin history table.

## What you see

```text
VERSION    RELEASED    STATUS
2.1.284    2026-09-28  pinned, active, latest
2.1.283    2026-09-25  formerly pinned (0.4.0 to 0.7.0)
2.1.282    2026-09-24  unverified
...
2.1.270    2026-09-12  formerly pinned (0.1.0 to 0.3.2)
```

- **formerly pinned** names the first and last Termux Muscle releases that were accepted with that version. Such releases are always listed, like pinned, active and retained ones.
- **unverified** now means what it says: no Termux Muscle release was ever accepted with that version.
- `--json` adds a `formerly_pinned` field per release (the history entry, or null) and the manifest's `pin_history` array; the schema stays `termux-muscle.available.v1`.

## Known limitations

- Installing any version other than the current pin, including a formerly pinned one, still needs `update --claude-version X.Y.Z --allow-unverified`. Whether a formerly pinned version should be installable without that flag is a policy question left open for a later release.
- History entries require a registered maintainer report. A version verified outside this repository is not relabelled until its report is added.
- A manifest from a release before 0.9.0 has no history; the listing still works and shows only `pinned` and `unverified`.

## Device evidence

[Dated device evidence](../../compatibility/galaxy-s26-ultra-0.9.0-20260929.md) from a Samsung Galaxy S26 Ultra (Android 16, Termux 0.118.3) covers `make check` (all 15 test programs passed in a native Termux shell, including the pin history regressions) and maintainer acceptance: private source installation, isolated startup, offline update and rollback, removal and one bounded authenticated **Opus 5.5** shell-tool workflow, with the live installation unchanged. The report binds to the tested source commit and a clean tree.

Run acceptance from a **fresh native Termux shell that is not inside Claude Code**, in a clean checkout of the release commit:

```sh
make check
scripts/maintainer_acceptance.sh --model claude-opus-5-5
```

## Updating an existing installation

From a fresh Termux shell:

```sh
termux-muscle self-update
```

The runtime does not change: `termux-muscle update` reports 2.1.284 as already the pinned release.
